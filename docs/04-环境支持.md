## 三、平台中立块如何工作

本方案的核心设计：**块内不写死盘符**，改为按平台列出取值。

```markdown
- 无 git 跟踪的用户级文件，改前备份到本平台备份根，写入前核对目标盘可用与空间，写入后逐文件校验：
  - Windows Codex：`E:\CodexBackups\<类别>\<时间戳>`
  - WSL：`/mnt/e/CodexBackups/<类别>-<时间戳>/`
  - opencode：`E:\OpenCodeBackups\<类别>\<时间戳>`（**不与 Codex 备份混放**）
```

**为什么这样做**

若不这样做，每个平台需要一份块变体：

| 方案 | 变体数量 | 同步方式 |
|---|---|---|
| 平台专属块 | 随平台数增长 | 人眼比对（必然漂移） |
| **平台中立块** | **恒为 1** | **SHA256 机械校验** |

**代价**：块比平台专属版本略长（多了两行路径说明）。
**收益**：同步可机械验证，这是本方案能跨三平台保持一致的根本原因。

## 四、换行策略

仓库用 `.gitattributes` 统一换行，避免 Windows/WSL 双平台产生 diff 噪声：

```gitattributes
# 仓库内一律 LF
* text=auto eol=lf
*.md  text eol=lf
*.py  text eol=lf
*.sh  text eol=lf

# Windows 专属脚本保留 CRLF
*.ps1 text eol=crlf
*.cmd text eol=crlf
*.bat text eol=crlf
```

**要点**

- `text=auto` 让 git 自动识别文本文件
- `eol=lf` 保证**工作区**也是 LF（仅设 `text` 只影响仓库存储）
- PowerShell / cmd 脚本必须 CRLF，否则部分 Windows 工具会报错
- **二进制文件显式标 `binary`**，避免被误判为文本而损坏

## 五、各平台已知陷阱

### WSL / Linux

#### 1. DrvFs 上 `cp -p` 失败

```bash
cp -p src dst   # cp: preserving times for 'dst': Operation not permitted
```

**原因**：`/mnt/c`、`/mnt/d`、`/mnt/e` 是 DrvFs，不支持 `utimes`。

**解决**：用普通 `cp`，改用 **SHA256 校验**确认复制成功（不依赖时间戳）。

#### 2. `projectRoot` 判定被父目录空仓库干扰

多数工具用"含 `.git` 的最近祖先目录"判定项目根。父目录里一个 0 提交的空仓库
会让所有子目录都被判定归属它，进而影响技能发现与规则加载。

**排查**

```bash
cd <某个子目录> && git rev-parse --show-toplevel
```

#### 3. WSL 发行版被回收导致服务中断

WSL 2.6+ 存在已知行为：**最后一个终端关闭后约 15-20 秒无条件回收发行版**，
systemd 用户服务也可能被带走（[microsoft/WSL#13416](https://github.com/microsoft/WSL/issues/13416)）。

**与规则的关系**：若你的 Agent 服务跑在 WSL 里，会话中断会导致规则加载失效。
常见缓解：保留一个隐藏交互会话、`loginctl enable-linger`、关闭 snapd standby。

---

### Windows

#### 1. 全局 Git 身份可能在某个平台缺失

Git 身份是**按用户配置**的，Windows 侧配好不代表 WSL 侧配好。

**验证**

```powershell
git config --global user.name
git config --global user.email
```

#### 2. 备份根不可用时**必须停止**，不得静默回退

本方案规定：备份盘不可用或空间不足时**停止并报告**，
**不得**自动把备份写到 C/D（那会污染系统盘，且违反"备份与源分离"的初衷）。

#### 3. PowerShell 结果变量命名冲突

```powershell
# 错误：$matches 会被 -match 自动覆盖
$matches = Get-ChildItem | Select-String "foo"

# 正确：换名
$hits = Get-ChildItem | Select-String "foo"
```

`$Matches` 是 PowerShell 的自动变量（大小写不敏感），业务变量用它会导致结果被静默覆盖。

#### 4. `git add` 的路径分隔符

Windows 上 `git add` 接受正斜杠与反斜杠，但**跨 WSL 调用时**建议统一用正斜杠，
避免转义问题。

## 六、新增平台时需要改什么

只需改**一处**——托管块里的备份根列表（下面是 diff 示意，`+` 行为新增）：

```diff
  - Windows Codex：`<盘符>:\CodexBackups\<类别>\<时间戳>`
  - WSL：`/mnt/<小写盘符>/CodexBackups/<类别>-<时间戳>/`
  - opencode：`<盘符>:\OpenCodeBackups\<类别>\<时间戳>`
+ - <新平台>：`<该平台的备份根>/<类别>/<时间戳>`
```

改完后（**用你自己的块文件**，不是仓库里的公开模板）：

```bash
# 同步到所有目标
python3 scripts/sync_block.py --block <你的块文件> --targets local/targets.txt --apply

# 校验（必须 n/n 全一致）
python3 scripts/verify_blocks.py --block <你的块文件> --targets local/targets.txt
```

**注意**：新增平台属于**块内容变更**，会改变块哈希，
因此**所有**目标项目都需要重新同步——这正是要让同步可机械执行的原因。

若变更较大，建议**升版本号**（`v2` → `v3`），使新旧块可区分：

```markdown
<!-- GLOBAL-PROJECT-LOG-RULES:START v3 -->
```

## 七、跨平台检查清单

部署或排障时按此清单核对：

```bash
# 1. Git 身份（每个平台都要查）
git config --global user.name && git config --global user.email

# 2. Agent 规则入口（每个平台都要查）
ls -la "$HOME/.codex/AGENTS.md" "$HOME/.config/opencode/AGENTS.md"

# 3. 技能根
ls -la "$HOME/.agents/skills/"

# 4. 项目块一致性
python3 scripts/verify_blocks.py --block configs/block/GLOBAL-PROJECT-LOG-RULES.v2.md \
        --targets targets.txt

# 5. 备份根可用性与空间
df -h /mnt/e 2>/dev/null || echo "备份盘不可用 —— 按规则应停止并报告"

# 6. 换行是否被污染
git ls-files --eol | grep -v "lf" | head
```

第 6 条用于发现 CRLF 污染：`git ls-files --eol` 输出中 `i/lf w/lf` 表示索引与工作区均为 LF，
若出现 `w/crlf` 说明工作区被 Windows 工具改写了换行。
