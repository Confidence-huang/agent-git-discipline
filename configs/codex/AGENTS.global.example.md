## 代码修改的 Git 闭环

- 任何代码、脚本、构建配置或测试代码修改前，先定位真实 Git 根目录并核对 branch、HEAD、
  index、工作树和目标文件状态；不得在不知道仓库边界时直接写代码。
- 用户已全局授权把"本轮代码改动的本地 Git commit"作为默认收尾动作，
  不再为每个普通本地 commit 重复确认。每完成一个可独立验证的原子改动，
  立即运行相关测试/构建，检查 `git diff` 与 `git status`，只暂存本轮明确范围并创建
  信息清楚的 commit；**不能积攒多轮代码改动后一次混合提交**。
- 禁止使用 `git add -A`、`git add .` 或其他宽范围暂存来顺手带入用户已有修改、
  无关未跟踪文件、构建产物、凭据或机器配置。提交前必须复核 staged diff；
  发现范围外文件立即取消该文件的暂存，**但不得丢弃用户内容**。
- 项目没有 Git、仓库尚无首个提交或缺少可信基线时，先建立范围明确、可恢复的项目级基线。
  若安全基线会卷入大量历史文件、秘密、缓存或归属不明修改，
  **停止代码写入并请求用户确认基线范围**，不能用"先改完再说"绕过 Git。
- `PROJECT_LOG.md`、相关测试和与该原子改动直接对应的技术文档可以随同提交；
  生成物是否入库服从项目 `.gitignore` 和既有政策。
  **提交失败时必须报告 `GIT_BLOCKED`**，不得把未提交代码声称为完成。
- 本地普通 commit 的持续授权**不包含**新建/切换分支、rebase、reset、改写历史、tag、
  push、PR 或远端操作；这些仍按任务范围和外部影响**单独确认**。
- 每次成功本地 commit 后，用 `git rev-list --first-parent --count HEAD` 计算该仓库连续
  Git 编号，并在项目日志记录"第 N 次 git"、完整 commit SHA 和提交范围。
  最终回复的**最后一条普通文本**必须是 `已git：<仓库> 第 N 次 git（commit <短SHA>）`；
  若本轮没有 commit，则明确写 `本轮未git：原因`，**不得伪造编号**。
- 涉及**多个仓库**时**逐个仓库各写一行**；单仓库也**不省略** `<仓库>`，否则事后分不清是哪一份回报。
- Git 根用 `git rev-parse --show-toplevel` 显式确认，不凭目录名假设。
  工作区起点若为脏：**用户自己的**改动先报告、不擅自提交或丢弃；
  **上一轮 agent 的**改动先提交或 `stash` 存档；**不回退与本轮无关的改动**。
- **原子性检验**（提交前自查）：只做一件事／代码库仍可工作／commit message 标题
  不需要出现"and"／能独立 revert 而不破坏其他功能／审查者无需外部上下文即可理解。
  若描述时必须说"和"，那就是两个 commit。改动横跨互不相关目录、
  或同一次混有 `feat` 与 `fix`/`chore`，应拆分；格式化噪声与逻辑改动分开提交。
- 改动里混有"该提交的"与"不该提交的"时，用 `git add -p` 逐块挑选，
  而不是先整体暂存再回退。
- 回退优先 `git revert`（保留历史，可安全推送）；`git reset --hard` 与 `git clean`
  属危险操作需单独授权；`git reflog` 是最后保险。
  `git push --force` 禁止，确需时只用 `--force-with-lease` 且限自己的分支。
- 秘密一旦提交进历史极难清除（需 `git-filter-repo`/BFG 重写历史，
  而重写历史本身需要单独授权），防线必须前移到"根本不提交"；`.gitignore` 本身应入库。
- 项目级 `AGENTS.md` 应包含 `GLOBAL-PROJECT-LOG-RULES` 托管块 **v4**
  （配对标记 `:START v4` … `:END`）。本节规则是该块的全局投影。

## 全局规则同步硬门槛

当用户纠正全局执行方式，或要求修复会影响后续所有会话的行为时，
**不能只改一个入口文件**。必须同步检查并按需更新所有规则入口，
修复完成后用**全文搜索**核对关键触发词是否已覆盖到对应入口。

不能只把新规则写进复盘日志、记忆摘要或单个项目文件——这些只能作为证据和补充，
**不能替代正式入口规则**。

## 备份位置

- 新建的恢复备份统一放在备份根 `<盘符>:\CodexBackups\<类别>\<时间戳>`
  （示例：`E:\CodexBackups\...` —— **请替换为你自己的备份盘符**），
  不把新备份载荷写入系统盘。
- 执行删除、覆盖、迁移、卸载、注册表或全局配置变更前，先核对备份盘可用且空间充足，
  再建立并**逐文件验证**备份。
- 备份盘不可用、空间不足或工具只能把备份写到系统盘时，
  **必须停止并向用户说明，不得自动回退**。
